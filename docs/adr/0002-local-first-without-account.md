# 0002. Local-first без аккаунта

## Статус

Принято, 2026-10-06.

## Контекст

- Критичный путь — ввод, даты, оценки, план дня — должен работать без сети (принцип 8 ТЗ).
- Для проверки главной гипотезы аккаунт не нужен. Он добавил бы в MVP аутентификацию, серверную БД и хранение персональных данных ([план, §2](../tech-plan.md#2-решения-по-открытым-вопросам), решения 1 и 4).
- Данные не должны теряться при переустановке и смене телефона (НФТ «Сохранность», ONB-2).

## Решение

- Источник правды — база Room `tasker.db` на устройстве. Настройки хранятся в DataStore. Аккаунта и входа нет.
- Сеть нужна только ИИ. Комментарий к разрешению `INTERNET` в манифесте `app` так и говорит: разрешение нужно для запросов к ИИ (с согласия) и к прокси, всё остальное работает без сети.
- Сохранность обеспечивают три механизма в `core:backup`:

| Механизм | Что делает | Где в коде |
| --- | --- | --- |
| Экспорт | ZIP через системный выбор файла: `export.json` и `tasks.md` | `ExportService` |
| Ежедневная копия | `BackupWorker` раз в 24 часа, если заряд не низкий; первый запуск ночью, в 03:00. Хранятся 7 ежедневных и 4 еженедельные копии. По желанию копия пишется ещё и в папку пользователя | `BackupScheduler`, `BackupService`, `BackupRotation` |
| Android Auto Backup | В облачную копию и при переносе на новый телефон попадают только `backups/latest.json.gz` и `datastore/settings.json`. Живая база туда не попадает | `backup_rules.xml` и `data_extraction_rules.xml` в `core/backup/src/main/res/xml/` |

- **Восстановление.** Если при запуске база пуста и есть копия (ежедневная или возвращённая Auto Backup), приложение один раз предлагает восстановить её одним тапом (`RestoreService`). Файл экспорта можно импортировать вручную в настройках.
- **Ничего не заменяется молча.**
  - Импорт в непустую базу возвращает `ImportResult.NotEmpty` и данные не трогает.
  - Замена возможна только после явного подтверждения. Перед заменой текущие данные сохраняются как копия дня.
  - Пустая база в копию не пишется: после переустановки такая копия затёрла бы ту, что нужна для восстановления.
- **Готовность к синхронизации без самой синхронизации.** Идентификаторы — UUIDv7 (`Ids.kt`), у задач и проектов есть `updatedAt`, все изменения пишутся в журнал событий ([ADR 0005](0005-commands-and-event-log.md)).

## Последствия

- По коду без сети не работает только ИИ. Проверки в режиме полёта на устройстве не было.
- Приложение работает на одном телефоне. Перенести данные можно через Auto Backup или через экспорт и импорт.
- Облачная копия отстаёт от живых данных: в неё попадает последняя ежедневная копия, а не текущее состояние базы.
- Если Auto Backup выключен, при потере телефона данные спасут только экспорт и копия в выбранной пользователем папке.
- Ключ API и токен прокси в копии не попадают (`noBackupFilesDir`). После восстановления ключ нужно ввести заново ([ADR 0006](0006-ai-access-by-install-channel.md)).

## Альтернативы

- **Свой аккаунт и синхронизация через сервер.** Не в MVP: аккаунт появится в L3 вместе с Telegram ([план, §2](../tech-plan.md#2-решения-по-открытым-вопросам)).
- **Auto Backup живой базы.** Отвергнут: мешают WAL и версии схемы. Сжатый JSON проще и укладывается в лимит 25 МБ ([план, §16](../tech-plan.md#16-экспорт-и-резервные-копии)).
