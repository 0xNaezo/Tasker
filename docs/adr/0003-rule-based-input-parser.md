# 0003. Собственный парсер ввода на правилах; ИИ только дозаполняет

## Статус

Принято, 2026-10-06.

## Контекст

- Задачу вводят одной строкой, например «пт до 18:00 сдать отчёт #client M». Поля нужно распознавать прямо при наборе и показывать чипами (CAP-2…CAP-5).
- Ввод должен работать без сети и никогда не ждать ИИ (принцип 8 ТЗ, CAP-7).
- Языки разбора — русский, украинский и английский ([план, §2](../tech-plan.md#2-решения-по-открытым-вопросам), решение 5).
- Бюджет плана — не больше 2 мс на типичную строку на эталонном устройстве. Регулярные выражения с катастрофическим перебором запрещены ([план, §9.1](../tech-plan.md#91-конвейер)).

## Решение

- Разбор живёт в модуле `core:parser` — чистый Kotlin без Android SDK (плагин `tasker.jvm.library`).
- Конвейер разбора — `InputParser`. Движок общий для всех языков. Языковой пакет (`LanguagePack`, `LanguagePacks`) содержит только словари: слова дат, маркеры дедлайна, слова горизонта. Фразы из нескольких слов хранятся в префиксных деревьях (`PhraseTrie`).
- Какие пакеты включены, решает `ParserProvider` в `core:data`: выбор пользователя, а без него — языки системы ([ADR 0009](0009-implementation-interpretations.md), п. 10).
- Порядок в дате «12/10» зависит от региона. Месяц стоит первым для US, PH, FM, MH и PW, в остальных регионах первым идёт день (`ParserProvider.slashDateOrder`).
- Качество держат тесты. CI запускает их на каждый PR в составе `./gradlew unitTests`:
  - golden-корпус `core/parser/src/test/resources/golden/{ru,uk,en}.tsv` — сейчас 271, 212 и 207 случаев. `GoldenCorpusTest` требует не меньше 150 случаев на язык;
  - property-тесты инвариантов разбора (`ParserPropertyTest`);
  - микробенчмарк `ParserPerformanceTest`: среднее время разбора типичной строки на JVM меньше 2 мс.
- ИИ работает только после правил и только дозаполняет:
  - задача попадает в очередь ИИ, только если ИИ включён, у задачи нет оценки и она не выполнена (`CaptureService`);
  - приоритет источников поля — USER > PARSER > INTEGRATION > AI > DEFAULT (`FieldProvenance`). ИИ пишет только в пустые поля и в поля с источником AI или DEFAULT;
  - если текст задачи изменился после запроса, ответ отбрасывается: `AiCommands` сверяет SHA-256 текста.

## Последствия

- Разбор локальный и детерминированный: одна и та же строка при тех же времени и настройках даёт тот же результат.
- Ошибку разбора исправляют правилом или словарём и закрепляют golden-случаем.
- Формулировки вне словарей и шаблонов парсер не распознаёт. Если ИИ включён и у задачи нет оценки, ИИ предложит оценку и даты, которые не нашли правила.
- Повторы («каждый понедельник») парсер не разбирает: такая дата не становится датой задачи (`LanguagePack.blockingWords`).
- Время разбора измерено только на JVM. На телефоне его не мерили.

## Альтернативы

- **LLM для разбора каждой строки.** Отвергнута: нужны сеть и согласие пользователя, ответ приходит не мгновенно.
- **Модель на устройстве.** Отложена: по плану такие модели есть на ограниченном круге телефонов и слабее на ru и uk ([план, §2](../tech-plan.md#2-решения-по-открытым-вопросам), решение 2). Интерфейс `AiGateway` позволяет добавить её позже.
