# 0011. ИИ-провайдер — OpenRouter

## Статус

Принято, 2026-10-06. Заменяет провайдера и модель из [ADR 0006](0006-ai-access-by-install-channel.md). Доступ к ИИ по каналу установки остаётся прежним.

## Контекст

- План выбрал Claude API и официальный Anthropic Java SDK ([план, §17.4](../tech-plan.md#174-модель-и-параметры-api)). Так и было сделано: модуль `core:ai-claude`, [ADR 0006](0006-ai-access-by-install-channel.md).
- Владелец продукта решил перевести ИИ на OpenRouter: один ключ и один счёт для моделей разных поставщиков.
- Требования плана остаются в силе ([§17.4](../tech-plan.md#174-модель-и-параметры-api), [§18.1](../tech-plan.md#181-ии-прокси-для-сборок-из-google-play), [§21](../tech-plan.md#21-безопасность-и-приватность)):
  - ответ — структурированный, по JSON Schema маршрута;
  - глубина рассуждений задаётся явно;
  - стабильный префикс промпта помечен для кэша;
  - бюджет прокси учитывает стоимость каждого вызова;
  - ни ключ, ни тексты задач не попадают в журналы.

## Решение

**Модуль.** `core:ai-openrouter` (чистый Kotlin) заменяет `core:ai-claude`, Anthropic Java SDK из проекта удалён.

- `OpenRouterRouteRunner` выполняет маршруты `core:ai-contract` запросом `POST https://openrouter.ai/api/v1/chat/completions` через клиент Ktor.
- HTTP-движок передаёт вызывающий: OkHttp в приложении, в backend и в `tools/ai-eval`, `MockEngine` в тестах.
- У клиента нет плагина журналирования.

**Запрос** ([`OpenRouterRouteRunner.kt`](../../core/ai-openrouter/src/main/kotlin/app/tasker/core/ai/openrouter/OpenRouterRouteRunner.kt)):

- модель — идентификатор OpenRouter, по умолчанию `anthropic/claude-opus-5.5` (`RouteSettings.DEFAULT_MODEL`, `AiSettings.DEFAULT_MODEL`);
- `reasoning.effort` — из настроек маршрута (`AiRoute`), как раньше `effort`. Текст рассуждений в ответ не включается (`reasoning.exclude`), но оплачивается;
- `response_format` — JSON Schema маршрута в строгом режиме;
- `provider.require_parameters: true` — только конечные точки, которые поддерживают все параметры запроса, в том числе строгую схему;
- `provider.zdr: true` — только конечные точки, которые не хранят запросы и ответы (Zero Data Retention). Выключается настройкой маршрута `zeroDataRetention`, на backend — переменной `ROUTE_<ROUTE>_ZDR=false`. Приложение её не меняет;
- системный промпт идёт первым, с пометкой `cache_control`; переменные данные — в сообщении пользователя.

**Ответ.**

- Сначала проверяется `finish_reason`:
  - `content_filter` или сообщение `refusal` — отказ модели;
  - `length` — ответ обрезан по `max_tokens`;
  - `error` — сбой поставщика.
- Затем содержимое разбирается по схеме, и маршрут проверяет его смысл — как раньше.
- Ошибки HTTP сводятся к `FailureKind`:
  - 401, 402 (нет кредитов) и 403 — нет доступа;
  - 403 с причинами модерации — отказ;
  - 408 — сеть;
  - 429 — лимит;
  - 5xx — перегрузка;
  - 400 и 404 — ошибка запроса. 404 приходит и тогда, когда нет подходящей конечной точки.
- Текст ошибки OpenRouter не читается: он может цитировать запрос.

**Повторы.** Сбой, за который ничего не списано (408, 429, 5xx, нет соединения, тайм-аут), повторяется внутри вызова. Пауза перед повтором начинается с секунды и удваивается.

| Где | Повторов | Тайм-аут попытки |
| --- | --- | --- |
| Приложение, `tools/ai-eval` | до двух | 60 секунд |
| Backend | один | 30 секунд |

**Стоимость.**

- OpenRouter сообщает, сколько списал за вызов (`usage.cost`). Это значение пишут бюджет прокси и отчёт eval (`RouteUsage.costMicroUsd`).
- Таблица `ModelPricing` с идентификаторами OpenRouter оценивает только вызовы без этого поля.
- `prompt_tokens` у OpenRouter включает чтение и запись кэша. В `RouteUsage` они разведены, поэтому каждый токен оценивается один раз.

**Ключ.**

- Прямой режим: пользователь вводит ключ API OpenRouter (`sk-or-…`). Хранение прежнее: `ApiKeyStore`, секрет `openrouter_api_key`.
- Ключ должен быть печатным ASCII без пробелов: он уходит в заголовок `Authorization`. Это проверяют `ApiKeyStore.normalize` и конфигурация backend.
- Backend: переменная `OPENROUTER_API_KEY`. Адрес `OPENROUTER_BASE_URL` — только `https://`.

**Серверные фолбэки Claude API** (`fallbacks: "default"`) убраны вместе с SDK. Настройка маршрута `fallbacks` и переменная `ROUTE_<ROUTE>_FALLBACKS` заменены на `zeroDataRetention` и `ROUTE_<ROUTE>_ZDR`.

## Последствия

- Тексты задач идут в OpenRouter, а оттуда — к поставщику модели. С `zdr` и строгой схемой у `anthropic/claude-opus-5.5` подходят только конечные точки Google Vertex AI (данные OpenRouter на 2026-10-06). Собственный API Anthropic в список ZDR не входит. Черновики [политики конфиденциальности](../privacy-policy.md) и [ответов Data safety](../play-data-safety.md) обновлены, но их нужно сверить с условиями OpenRouter и поставщиков.
- Если нет конечной точки, которая выполняет `zdr` и `require_parameters`, запрос отклоняется как ошибка запроса. Ответа в другом формате или без ZDR не будет. Другую модель стоит проверить на это до переключения.
- Бюджет прокси считается по сумме, которую списал OpenRouter.
- Ключи Anthropic больше не подходят.
  - Ключ, сохранённый прежней сборкой, не читается: пользователь вводит ключ OpenRouter.
  - Модель без префикса поставщика, сохранённая прежней сборкой, заменяется моделью по умолчанию (`DirectAiGateway.routeSettingsFor`).
- Вызовы OpenRouter проверены только на фейке (`MockEngine`), не на настоящем API.

## Альтернативы

- **Оставить Claude API и Anthropic Java SDK.** Отклонено решением владельца продукта.
- **Клиент OpenAI-совместимого SDK.** Отклонён: маршрутам нужны поля OpenRouter (`provider`, `reasoning`, `usage.cost`), а Ktor уже есть в приложении и на backend.
- **Без `zdr`, на условиях аккаунта OpenRouter.** Доступно настройкой маршрута на backend, но не по умолчанию. Тексты задач — личные данные, а с `zdr` их обрабатывает только поставщик без хранения.
