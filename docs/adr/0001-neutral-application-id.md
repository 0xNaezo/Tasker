# 0001. Нейтральный applicationId, один идентификатор и один ключ для двух каналов

## Статус

Принято, 2026-10-06.

## Контекст

- `applicationId` нельзя изменить после первой загрузки в Google Play. Рабочее название продукта не утверждено, а отображаемое название можно менять когда угодно ([план, §2](../tech-plan.md#2-решения-по-открытым-вопросам), решение 7).
- Приложение распространяется двумя каналами: до беты — APK из GitHub Releases, с этапа M10 — Google Play ([план, §24](../tech-plan.md#24-cicd-и-выпуск)).
- APK с другим ключом подписи не встанет поверх установленного. Приложение придётся удалить, а вместе с ним и локальные данные ([план, §24.3](../tech-plan.md#243-подпись)).

## Решение

- `applicationId = "io.github.oxnaezo.tasks"`. В идентификаторе нет названия продукта.
- Код и ресурсы живут в пространствах имён `app.tasker.*`: `app.tasker` у приложения, `app.tasker.core.*`, `app.tasker.feature.*` и `app.tasker.widget` у модулей. `namespace` пользователь не видит, и с `applicationId` он не связан.
- Каналы `github` и `play` — флейворы одного измерения `channel`. `applicationId` у них общий: `applicationIdSuffix` нет ни у флейворов, ни у типов сборки.
- Релизы обоих каналов подписываются одним ключом. Ключ хранится вне репозитория (см. [README, «Подпись релиза»](../../README.md#подпись-релиза)). В CI APK канала `github` и бандл канала `play` подписывает одно и то же хранилище из секрета `TASKER_KEYSTORE_BASE64`.

Где в коде: [`app/build.gradle.kts`](../../app/build.gradle.kts) — `applicationId`, `productFlavors`, `signingConfigs`; [`.github/workflows/release.yml`](../../.github/workflows/release.yml) — подпись в CI.

## Последствия

- Сборку из GitHub можно обновить сборкой из Google Play без переустановки и без потери данных. Для этого в Play App Signing загружают тот же ключ ([план, §24.3](../tech-plan.md#243-подпись)).
- Две сборки разных каналов не встанут на один телефон рядом: вторая заменит первую.
- При смене канала данные остаются, а выбранный режим ИИ — нет. Режим из сборки другого канала считается невыбранным ([ADR 0006](0006-ai-access-by-install-channel.md)).
- У `debug` тот же идентификатор, но другой ключ — отладочный. Debug-сборка не встанет поверх релизной, и наоборот: сначала нужно удалить приложение вместе с данными. Перед этим стоит сделать экспорт.
- На этот идентификатор опираются отладочные команды adb (`-p io.github.oxnaezo.tasks`, см. README) и макробенчмарки (`PACKAGE_NAME` в `baselineprofile/src/main/kotlin/app/tasker/baselineprofile/AppJourneys.kt`).

## Альтернативы

- **Идентификатор с названием продукта.** Отвергнут: название может смениться, а идентификатор — нет.
- **Отдельные идентификаторы каналов** (суффиксы `.github`, `.play`). Отвергнуты: переход из GitHub в Google Play стал бы новой установкой без данных. План требует, чтобы у каналов были общие `applicationId`, ключ подписи и данные ([§24.1](../tech-plan.md#241-сборки-и-проверки)).
