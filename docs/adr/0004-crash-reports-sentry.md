# 0004. Отчёты о сбоях: Sentry только с DSN и с согласия пользователя

## Статус

Принято, 2026-10-06.

## Контекст

- План оставил выбор между Crashlytics и Sentry на этап M0 ([план, §5](../tech-plan.md#5-стек-и-минимальные-версии)).
- Тексты задач не должны попадать ни в системный журнал, ни в отчёты о падениях ([план, §21](../tech-plan.md#21-безопасность-и-приватность)).
- Данные пользователя уходят с телефона только с его согласия (НФТ «Приватность»).

## Решение

- Отчёты о сбоях собирает Sentry Android SDK (`io.sentry:sentry-android` 8.59.0).
- Автоинициализация SDK выключена: `io.sentry.auto-init=false` в манифесте. SDK запускает класс `CrashReporting` в модуле `app`.
- DSN задаётся при сборке свойством Gradle `tasker.sentryDsn` и попадает в `BuildConfig.SENTRY_DSN`. Без DSN `CrashReporting.start()` сразу выходит, и SDK не запускается.
- С DSN отчёты уходят только после согласия. Согласие — настройка `telemetryConsent`, по умолчанию `false`; в настройках это переключатель «Отправлять отчёты о сбоях». Выключение закрывает SDK (`Sentry.close()`).
- Из отчёта убирается всё, что может содержать текст пользователя:
  - SDK не собирает персональные данные (`isSendDefaultPii = false`), «хлебные крошки» (`maxBreadcrumbs = 0`), скриншоты и иерархию экранов;
  - `beforeSend` вызывает `withoutUserText()`: обнуляет сообщение, значения исключений, крошки и пользователя, очищает `extras`.

  От самого сбоя остаются тип исключения и стек вызовов. Стандартный контекст, который Sentry SDK добавляет сам (модель устройства, версия Android), код не отключает.
- Метки отчёта: `release` = `<applicationId>@<versionName>+<versionCode>`, `environment` = `<канал>-<тип сборки>`, например `github-release`.

Где в коде: [`CrashReporting.kt`](../../app/src/main/kotlin/app/tasker/platform/CrashReporting.kt), [`app/src/main/AndroidManifest.xml`](../../app/src/main/AndroidManifest.xml), [`app/build.gradle.kts`](../../app/build.gradle.kts).

## Последствия

- Сборка без `-Ptasker.sentryDsn=…` ничего не отправляет, даже с согласием. DSN в репозитории нет: релизный workflow берёт его из секрета `TASKER_SENTRY_DSN`, если секрет задан (`.github/workflows/release.yml`). Локальные сборки по умолчанию идут без DSN.
- Переключатель в настройках виден и в сборке без DSN, но там ни на что не влияет.
- Сообщения исключений теряются, поэтому сбой разбирают по типу исключения и стеку.
- SDK включается, только когда при старте прочитаны настройки. Сбой до этого момента в отчёт не попадёт.
- Отдельного теста на очистку событий (`withoutUserText`) нет.
- Согласие `telemetryConsent` сейчас управляет только отчётами о сбоях. Недельные агрегаты метрик ([план, §23](../tech-plan.md#23-метрики-и-телеметрия), маршрут `/v1/metrics`) приложение не отправляет.

## Альтернативы

- **Crashlytics** — второй кандидат из плана. Почему выбран Sentry, ни в плане, ни в коде не записано.
